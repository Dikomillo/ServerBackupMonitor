# Server Backup Monitor

Windows-приложение для резервного копирования и мониторинга удалённых Linux-серверов по SSH. Архитектура компонентная: готовые компоненты покрывают x-ui, Docker-стек и статические сайты с Nginx; новые наборы путей можно добавлять без изменения формата архивов. Работает на стандартной библиотеке Python, использует существующие SSH-ключи и не хранит пароли.

## Возможности

- GUI без консоли и отдельный текстовый режим;
- мониторинг интернета, SSH, x-ui, URL панели, Nginx, сайтов и Docker-контейнеров;
- SSH по IPv6 и автоматическая проверка панели по IPv6, если IPv4 недоступен;
- любое количество серверов из одного `config.json`;
- конфигурационный дифф без реакции на счётчики трафика и последние подключения;
- один датированный ZIP с полной структурой серверов;
- загрузка только изменившихся компонентов;
- проверка SHA-256 и целостности SQLite;
- автоматическое хранение заданного количества последних архивов;
- полный проверяемый бэкап OpenWrt-роутера и локальный бэкап настроек приложения из GUI;
- скрытие и копирование IP, копирование событий.

## Требования

На Windows:

- Windows 10 или 11;
- Python 3.10+ с Tkinter;
- OpenSSH Client (`ssh` и `scp` в PATH);
- настроенный SSH-ключ для каждого сервера — вход по паролю не поддерживается.

На сервере:

- Linux, Python 3 и доступ по SSH;
- 3x-ui с базой `/etc/x-ui/x-ui.db` и сервисом `x-ui`;
- права на чтение системных настроек — обычно используется `root`.

Компонент `stack` дополнительно сохраняет стандартные пути `/root/docker-compose.yml`, `/root/.wg-easy`, `/root/.nginx` и `/opt/outline`. Отсутствующие пути безопасно пропускаются.

Компонент `site` сохраняет статический сайт из указанного `site_root` и конфигурацию `/etc/nginx`. `site_root` нужно явно указать для каждого сайта; публичные примеры используют `/var/www/example.com`. Сертификаты из `/root/cert` уже входят в компонент `x-ui`.

## Обязательная настройка SSH-ключа

Монитор запускает SSH с `BatchMode=yes`, поэтому не запрашивает и не сохраняет пароли. Для каждого сервера обязательно должен работать вход по ключу.

1. Создайте ключ в PowerShell, если его ещё нет:

   ```powershell
   ssh-keygen -t ed25519
   ```

2. Добавьте публичный ключ на сервер, заменив адрес:

   ```powershell
   Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub" | ssh root@203.0.113.10 "umask 077; mkdir -p ~/.ssh; cat >> ~/.ssh/authorized_keys"
   ```

3. Один раз подключитесь вручную и подтвердите отпечаток сервера:

   ```powershell
   ssh root@203.0.113.10
   ```

4. Убедитесь, что повторный вход выполняется без пароля. Повторите настройку для каждого сервера.

Если используется другой ключ, укажите его в поле `key`. Монитор использует строгую проверку ключа сервера, поэтому предварительное ручное подключение обязательно добавляет сервер в `known_hosts`.

## Быстрый запуск

1. Скачайте или клонируйте репозиторий.
2. Дважды запустите `start_monitor.vbs`.
3. При первом запуске рядом появится приватный `config.json`.
4. Укажите свои серверы в `config.json` и снова запустите `start_monitor.vbs`.

`config.json` исключён из Git и не должен публиковаться. Безопасный шаблон находится в `config.example.json`.

## Конфигурация

Общие настройки задаются один раз:

| Поле | Назначение | Значение по умолчанию |
|---|---|---:|
| `backup_root` | Папка резервных копий; относительный путь считается от папки программы | `backups` |
| `status_interval_seconds` | Интервал проверки доступности | `3600` |
| `backup_interval_seconds` | Интервал проверки изменений | `18000` |
| `retention_count` | Количество хранимых ZIP | `30` |
| `lock_port` | Локальный порт защиты от двойного запуска | `47651` |
| `router_backup` | Необязательные параметры полного бэкапа OpenWrt; пример ниже | `null` |

Каждый объект в `servers` описывает один сервер:

| Поле | Обязательное | Назначение |
|---|---|---|
| `host` | да | IP или DNS для SSH |
| `ssh_host` | нет | Отдельный IPv4/IPv6-адрес SSH; IPv6 также используется как запасной адрес панели |
| `panel_url` | да | Полный URL панели вместе с портом и базовым путём |
| `site_url` | только для `site` | Полный HTTP(S)-адрес сайта для проверки доступности |
| `site_root` | только для `site` | Безопасный абсолютный путь к файлам сайта; указывается явно |
| `name` | нет | Подпись в интерфейсе; по умолчанию используется `host` |
| `user` | нет | SSH-пользователь; по умолчанию `root` |
| `folder` | нет | Имя папки в архиве; безопасно создаётся из `host` |
| `components` | нет | `x-ui`, `stack` и/или `site`; по умолчанию `x-ui` |
| `key` | нет | Путь к отдельному SSH-ключу; поддерживаются `%USERPROFILE%` и `~` |

Чтобы добавить сервер, скопируйте один объект внутри массива `servers`. Код менять не требуется. Интерфейс показывает до трёх карточек сразу, остальные доступны горизонтальной прокруткой.

Минимальный объект нового сервера:

```json
{
  "name": "my-server",
  "host": "203.0.113.10",
  "panel_url": "https://203.0.113.10:2053/your-panel-path/",
  "components": ["x-ui"]
}
```

Если SSH доступен только по IPv6, оставьте основной URL панели в `panel_url`, а
адрес без квадратных скобок укажите в `ssh_host`, например
`"ssh_host": "2001:db8::2"`. Интерфейс показывает, по какому протоколу
ответила панель: IPv4 или IPv6.

Если на сервере также находятся WireGuard/Nginx/Outline в поддерживаемых стандартных путях, используйте `"components": ["x-ui", "stack"]`. Между объектами массива `servers` ставится запятая.

Для статического сайта используйте отдельный компонент `site`, сохраняя проверку панели x-ui:

```json
{
  "name": "static-site",
  "host": "203.0.113.30",
  "panel_url": "https://203.0.113.30:2053/your-panel-path/",
  "site_url": "https://www.example.com/",
  "site_root": "/var/www/example.com",
  "components": ["x-ui", "site"]
}
```

## Резервные копии

Архивы находятся в `<backup_root>/auto-backups` и называются:

```text
server-backup-YYYY-MM-DD_HH-MM-SS.zip
```

Внутри ZIP находятся папки каждого сервера и компонента, вложенные `.tar.gz`, метаданные и общий `manifest.json`. Для `site` в архив попадают файлы сайта и `/etc/nginx`; сертификаты остаются в архиве `x-ui`. При обычной проверке с серверов скачиваются только изменившиеся компоненты; неизменившиеся части берутся из локальной последней копии, поэтому каждая точка восстановления остаётся полной.

Если изменений нет, новый ZIP не создаётся. При превышении `retention_count` удаляется самый старый ZIP.

Счётчики трафика и последние подключения исключены только из сравнения. В резервную копию сама база 3x-ui попадает полностью. Логи и временные данные Prometheus не копируются. Монитор проверяет для `site` SSH, x-ui, Nginx, панель и HTTP-ответ сайта.

Кнопка `Бэкап настроек` создаёт проверенный ZIP с приватными `config.json`,
`state.json` и метаданными в `settings-backups/`. Эта папка исключена из Git.
Для восстановления закройте приложение и распакуйте `config.json` и
`state.json` из ZIP рядом с `backup_monitor.py`.

Для кнопки `Полный бэкап роутера` добавьте в `config.json`:

```json
"router_backup": {
  "script": "C:\\Tools\\RouterBackup\\backup-router.ps1",
  "target": "root@203.0.113.1",
  "destination": "router-backups"
}
```

Кнопка запускает указанный PowerShell-скрипт и сохраняет обычный OpenWrt-бэкап,
полный writable overlay, инвентари и все MTD-разделы. Независимые проверки
серверов и компонентов выполняются параллельно (не более
восьми задач), а задачи GUI не запускаются поверх друг друга. Каждый SSH/SCP —
отдельный процесс с таймаутом; `ControlMaster=no` запрещает постоянные
master-сессии.

После сброса загрузившегося роутера установите ту же версию OpenWrt и
восстановите полный overlay штатным скриптом восстановления. Если устройство
не загружается, сначала потребуется recovery/TFTP/UART. Raw MTD нельзя
автоматически переносить на другой экземпляр: Factory и bootloader могут быть
уникальны для устройства.

Перед восстановлением можно выполнить безопасную offline-проверку:
`restore-router.ps1 -VerifyOnly -BackupDirectory D:\\Backups\\router-snapshot`.
Она не подключается к роутеру и не меняет его.

## Управление

- `start_monitor.vbs` — GUI без окна консоли;
- `run_monitor.cmd` — GUI с консолью для диагностики;
- `install_startup.cmd` — добавить GUI в автозапуск Windows;
- `remove_startup.cmd` — удалить ярлык автозапуска;
- `python backup_monitor.py --once` — одна проверка;
- `python backup_monitor.py --force` — принудительный полный архив;
- `python backup_monitor.py --baseline` — запомнить состояние без скачивания;
- `python backup_monitor.py --self-test` — локальная самопроверка.

## Безопасность публикации

`.gitignore` исключает:

- `config.json` с IP, DNS, путями панелей и SSH-настройками;
- `state.json` с историей и отпечатками;
- `logs/`, `settings-backups/`, локальные архивы и Python-кэш.

Перед первой публикацией проверьте `git status`. Если приватный файл когда-либо уже попадал в коммит, одного `.gitignore` недостаточно: удалите его из истории и смените раскрытые базовые пути панели.

## Обновления, трей и уведомления

Версия программы отображается в окне. При появлении нового GitHub-релиза появится кнопка `Доступна v...`; она открывает страницу релиза и ничего не скачивает и не заменяет автоматически.

Обновление безопасное: заменяются только файлы программы из репозитория. Не удаляйте и не перезаписывайте свои `config.json`, `state.json`, `logs` и папку с архивами. При запуске новая версия сама добавляет недостающие настройки со значениями по умолчанию и сохраняет список серверов, пользователей и ключи.

Кнопка `В трей` скрывает окно, а монитор продолжает работать. Для значка и уведомлений установите зависимости:

```powershell
python -m pip install -r requirements.txt
```

Уведомления показываются для ошибок, предупреждений, сохранения точки восстановления и новой версии. Проверку релизов можно отключить в `config.json` параметром `check_updates: false`.
